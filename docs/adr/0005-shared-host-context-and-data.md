# 显式宿主上下文、共享项目数据与整目录迁移

状态：已接受。对应 #17、#18，延续 ADR-0002 与 ADR-0004。

## 决定

Claude Code 与 Codex 使用显式宿主入口 `deepseek-host.mjs <claude|codex>`，复用 `runCompanion`、dsh、worker、状态原子写入及现有作业锁，不复制执行核心，不引入 MCP。命令前可传 `--session-id`、`--transcript-source`；宿主上下文包含 `host`、`sessionId`、`workspaceRoot`、`transcriptSource`。缺失编号与来源为 `null`，不借另一个宿主的继承变量认领身份。Claude 入口保留既有 Claude 登记变量；Codex 入口只接受明确传来的身份，后续宿主登记由相应适配器提供。

新宿主入口统一使用 `DEEPSEEK_DATA_DIR`，默认 `~/.deepseek-plugin/`。其 `projects/<项目键>/` 保存候选、作业及日志，项目键沿用旧版本的路径哈希与 Windows 大小写规则；`hosts/` 留给宿主登记，使登记不占用项目迁移目标。真实 Claude 命令、子代理和会话结束清理均走新入口，不能任务写共享根而结束清理旧根。

底层 `deepseek-companion.mjs` 和 `deepseek-session.mjs` 保留直接调用兼容：未设置 `DEEPSEEK_DATA_DIR` 时仍使用 `CLAUDE_PLUGIN_DATA`，缺省回到旧默认数据根；旧项目目录直接位于该根下。显式设置 `DEEPSEEK_DATA_DIR` 时优先使用其 `projects/`。旧 `claudeSessionId` 保留原义，只能映射 Claude 归属，不可据当前 Codex 进程改写；作业的双宿主归属与生命周期由后续票实现。

## 显式迁移

`setup --migrate-from <旧插件数据目录>` 是独立分支，不查 dsh、不发连通性任务、不取消作业。普通 setup 只报告根目录与环境，不创建项目目录；已知旧路径仅作提示，不猜测 Claude 安装位置。SessionStart 不创建项目目录；共享 `projects/` 不存在时 SessionEnd 不创建空目录。用户可以先登记宿主或检查环境，再显式迁移。

迁移前须停止旧插件调用。迁移枚举源根下所有项目，按固定次序取得各磁盘项目的现有作业锁；无需从旧记录猜项目根。预检候选结构、明确终态（`completed`、`failed`、`cancelled`）、作业编号、配套普通日志和路径范围。活动作业、未知状态、损坏记录、缺失日志、不安全链接或未识别的数据文件均失败，不修改源记录、不恢复状态或终止进程。候选、作业及嵌套结果的未知字段保持原值；仅把日志路径改为目标位置。源目录保留。

迁移与新普通入口在 `projects/` 旁的 `.projects.publish/` 使用同一个锁协议。正常使用项目的入口在进入核心前，持此短锁准备项目目录；迁移持锁至发布。已有任何目标项目目录或文件即保守拒绝，目标不存在或空目录允许；根下 `hosts/` 等宿主登记不构成冲突。

完整快照写入同级私有暂存目录 `.projects.migration-<编号>.tmp/`，JSON 复用原子写入，最后一次目录 rename 发布 `projects/`。新建共享根、锁与暂存目录在 POSIX 使用 `0o700`，不更改用户已有目录或源目录权限。复制前后比对源文件快照及项目集合；发现并发旧写入即失败。旧底层前台写入不参与新发布锁，不能声称实现了与旧版本的在线同步；停止旧调用是迁移前提。

中断或写入失败只留下不可消费的同级暂存目录；普通入口看不到部分候选与作业。重新显式迁移会重建快照并复用已有进程实例核对回收退出进程的锁，不自动清理旧暂存目录。源、目标不允许互相包含，不执行覆盖合并或两段根目录替换。

## 取舍与验证

新布局增加一层 `projects/`，换取与宿主登记独立的单次发布。已初始化的空项目目录也视为冲突，因此应先迁移旧数据，再执行项目任务或查询候选。暂存文件可能在失败后保留，需用户按路径自行管理。

通过真实 CLI、fake dsh、合成 Claude 钩子输入和原生 Bash 命令验证共享候选、旧底层兼容、候选变化拒绝、全项目迁移与日志、未知字段保留、活动与路径阻断、故障及退出后重试、并发发布门闩。默认测试离线，不把回放当作实机证明。

文档核实：Context7 `/nodejs/node` 明确 `copyFileSync` 不保证原子性且跟随符号链接，因此不把递归复制直接暴露为可消费目标；先验证普通路径，再在同级暂存并以 rename 发布。
